# Revizorro Diff

Chrome-расширение для подсветки diff между итерациями код-ревью. Работает поверх существующей платформы ревью, добавляя визуальное сравнение версий кода прямо в интерфейсе.

## Возможности

- Построчная подсветка добавленных и удалённых строк (LCS diff)
- Бейджи на файлах: `новый` / `изменён` / `удалён`
- Статистика изменений на папках: `+5 ~3 -1`
- Общий список удалённых файлов с полными путями и просмотром прежнего кода, включая полностью удалённые папки
- Переключение между итерациями для сравнения
- Автоматическое обновление при навигации между работами и перерисовке кода.
- Сравнение по относительным путям при переименовании единственного корневого каталога проекта.

## Установка

1. Клонировать репозиторий
2. Открыть `chrome://extensions/`
3. Включить "Режим разработчика"
4. "Загрузить распакованное расширение" → выбрать папку `extension/`

## Структура

```
extension/
  manifest.json   — Manifest V3
  content.js      — Логика: парсинг данных, diff, DOM-инъекция
  line-diff.js    — Точный LCS diff с линейным расходом памяти
  review-history.js — Упорядочивание версий по дате сдачи
  content.css     — Стили подсветки и UI-компонентов
  popup.html/js   — Popup со статусом расширения
  icons/          — Иконки расширения
```

## Как работает

Расширение парсит данные из inline-скрипта страницы: текущего `window.wirthAdminBootstrap.data` или прежнего `__init__.default({}, data, ...)`. Парсер не выполняет JavaScript страницы и сохраняет исходники файлов без замены `undefined` внутри строк. Затем расширение строит индексы файлов и вычисляет точный LCS diff между выбранными версиями. Результат инжектится в DOM как подсветка строк и бейджи. Observer отслеживает перерисовку кода.

При смене URL работы расширение очищает старую подсветку и запрашивает HTML новой работы с текущей авторизацией на том же сайте. Запоздавшие ответы отменяются и не могут подменить новую работу. Сбой загрузки вызывает повторные попытки с увеличивающейся паузой. Лёгкая проверка URL каждые 250 мс обеспечивает обработку `pushState`, в том числе когда Diff выключен. Поэтому content script запускается на страницах `/office/*`, но данные ревью читает только на `/office/revisor-review/*`.

## Проверка

`npm ci` и `npm test` — тесты парсера, сопоставления файлов, diff, обработки DOM-мутаций, переходов между работами и popup на синтетических данных. Для DOM-тестов используется jsdom; само расширение не требует сборки или npm-зависимостей.

`node scripts/audit.cjs` — повторная проверка сценариев исходного аудита. Код выхода `1` означает воспроизведение дефекта.

## Сопоставление версий и ограничения

Если все файлы каждой версии лежат под одним корнем, имена корней отличаются и есть совпадения относительных путей, предыдущая версия сопоставляется с текущей без учёта имени корня. Например, `project-main/app/models.py` и `project-final/app/models.py` сравниваются как один файл. Содержимое сравнивается полностью; новые и удалённые файлы учитываются в статистике текущей папки. Оригинальные данные истории не меняются.

Несколько корней и переименования внутренних каталогов автоматически не объединяются. Неоднозначный сокращённый путь не получает подсветку вместо выбора произвольного файла.

История сортируется по `created_at`, текущая и более поздние версии исключаются. В списке показаны «Итерация 1», «Итерация 2» и далее — порядковые номера доступных версий после сортировки; дата сдачи доступна в подсказке. При отсутствующих или неоднозначных датах автоматическое сравнение не выбирается: нужно указать версию вручную.

Удалённые файлы показаны в общем раскрываемом списке независимо от текущего дерева папок; прежний код открывается по нажатию на путь. Это охватывает и полностью удалённый проект. Раскрытое состояние сохраняется при обычных обновлениях DOM и сбрасывается при смене сравнения.

Для файлов любого размера используется точный алгоритм Хиршберга с удалением общих префикса и суффикса. Память O(n+m), время в худшем случае O(n×m): очень большие и сильно различающиеся файлы могут потребовать заметного времени. Расчёт выполняется общей очередью короткими порциями с бюджетом около 8 мс, между которыми браузер обрабатывает события. Выключение Diff, смена сравнения и переход к другой работе отменяют незавершённые расчёты; устаревшие результаты не применяются. Приблизительный fallback отсутствует.
